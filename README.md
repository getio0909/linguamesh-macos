# LinguaMesh for macOS

LinguaMesh for macOS is the native SwiftUI and AppKit client for the LinguaMesh translation suite. The current prerelease slice contains a Swift Package executable that calls the generated LinguaMesh Core Swift wrapper, streams real core events, resolves a session-scoped provider secret from Keychain through the version-1 host-secret exchange, cancels active work, keeps partial output, and switches interface theme and locale without discarding text.

## Project authority

- [`GLOBAL_GOAL.md`](GLOBAL_GOAL.md) pins the global specification revision.
- [`REPOSITORY_ROLE.md`](REPOSITORY_ROLE.md) defines this repository's ownership boundaries.
- [`IMPLEMENTATION_STATUS.md`](IMPLEMENTATION_STATUS.md) records what is actually implemented and verified.

The authoritative specification lives in the sibling `linguamesh-project` repository. Product work must remain compatible with the pinned goal and a compatible LinguaMesh Core XCFramework.

## Native stack

The application uses Swift 6 language mode, strict concurrency, SwiftUI for its shell, and an AppKit `NSTextView` adapter for source and streamed output. `Sources/LinguaMeshFeature/CoreBridge/` is the only application module that imports the generated core wrapper. Credentials use an application-specific Keychain service; `UserDefaults` stores only theme, UI locale, and onboarding completion.

## Build and test on macOS

Check out `linguamesh-project`, `linguamesh-core`, `linguamesh-l10n`, and this repository as siblings, at the revisions recorded in `COMPATIBILITY.md`, then run:

```sh
cd ../linguamesh-core
bash tools/build-apple-sdk.sh
swift test --package-path bindings/apple
cd ../linguamesh-macos
bash tools/check-source.sh
swift build --configuration debug -Xswiftc -warnings-as-errors -Xswiftc -strict-concurrency=complete
swift test --configuration debug --parallel -Xswiftc -warnings-as-errors -Xswiftc -strict-concurrency=complete
bash tools/package-app.sh
```

The macOS workflow builds the sibling core XCFramework, runs unit and real-wrapper fake-provider integration tests (including the typed Keychain host-secret path), assembles an app bundle, and applies an ad-hoc signature for packaging verification. This is not distribution signing or notarization.

## Run the local translation slice

Start the credential-free core fake provider in one terminal:

```sh
cd ../linguamesh-core
cargo run --locked -p linguamesh-cli -- fake-provider --port 40123
```

Then launch the Swift Package executable from another terminal on macOS:

```sh
cd ../linguamesh-macos
swift run LinguaMesh
```

The default profile already points to `http://127.0.0.1:40123/v1/` and selects `fake-translator`. The provider binds only to loopback and requires no credential.

## Current limits

- Core protocol version 1 does not expose model discovery or provider-profile persistence. Model entry is manual and profiles are session-only; the typed host-secret exchange is implemented with a temporary local Protobuf codec until generated Swift messages are published.
- The committed localization catalog is generated by `linguamesh-l10n`; draft locales are labeled there and must not be represented as professionally reviewed.
- Document workflows, security-scoped bookmarks, signing, notarization, and stable packaging remain unimplemented.
